# TeamsExam 品牌视觉规范

## 目标与范围

TeamsExam 各模块的界面设计与实现均应遵循本规范。后台沿用 Geminus 提供的页面骨架和 Tabler 组件，以品牌色、信息层级及一致的页面组合表达产品自身风格。考试券模块是本规范当前已落地的示例；其他模块在新增或调整界面时也应遵循这些项目级原则。

视觉目标是专业、可信、清晰、便于处理日常运营任务。品牌表达通过克制的颜色和明确的信息层级实现，不以装饰效果取代数据和操作。

## 色彩

| 用途 | 色值 | 规则 |
| --- | --- | --- |
| Logo 天蓝 | `#0ea5e9` | 源自 TeamsExam 标志，用于品牌识别，不作为浅色模式下的小字号按钮底色 |
| 浅色主操作 | `#0369a1` | 主按钮、链接和主要交互；白色前景满足常规文字对比度 |
| 浅色主操作悬停 | `#075985` | 仅用于交互悬停状态 |
| 暗色链接 | `#7dd3fc` | 暗色模式下的链接 |
| 暗色链接悬停 | `#bae6fd` | 暗色模式下的链接悬停状态 |
| 暗色主操作 | `#38bdf8` | 暗色模式下使用明亮蓝色 |
| 暗色主操作前景 | `#082f49` | 暗色模式主色背景上的文字和图标 |
| 成功、警告、危险 | Tabler 语义色 | 只表达结果或状态，不作为品牌装饰色 |
| 页面与表面 | Tabler gray 基色 | 沿用后台底座现有的浅色/暗色表面，不在业务页另设背景色 |

浅色和暗色品牌主题值在 `admin/public/static/css/theme.css` 中通过 Tabler 主题变量全局配置，并由后台与公共布局加载，适用于 TeamsExam 整个项目。新增或调整界面时遵循本规范的品牌色和语义色规则；不要在模块视图中硬编码另一套主色。状态不能只靠颜色表达，需保留文字标签。

## 字体与层级

- 沿用 Tabler 与后台现有字体，不引入额外字体下载。
- 页面标题使用布局提供的 `page-title`；区块标题使用 `card-title`；字段名使用 `form-label`；辅助说明使用 `text-secondary` 与 `form-hint`。
- 数字统计可以突出字号，说明文字保持次级；列表中的主标识和状态应能快速扫读。
- 使用常规字重和清楚的留白区分层次，不用额外阴影、渐变或装饰性插画强调内容。

## 页面布局

- 沿用 Geminus 后台页面骨架、响应式容器、导航和页头，不在业务视图重复构建全局布局。
- 以 Tabler `card`、`card-header`、`card-body`、`card-footer` 组织相关内容；间距使用 Bootstrap/Tabler 网格和间距工具类。
- 页面标题与操作留在页头；表单按业务域分组，桌面端并列、窄屏端堆叠；长表格只在自身的 `.table-responsive` 容器内横向滚动。
- 一组相关行操作优先收纳在带文字的下拉菜单中，避免窄操作列导致图标纵向堆叠；危险操作继续与普通操作区分。

## 组件与状态

- 主操作使用 `btn-primary`，返回、取消等普通操作使用次级按钮；同一位置只突出一个主要动作。
- 图标沿用 Tabler Icons Webfont。纯图标按钮须提供本地化 `aria-label` 和 tooltip；带可见文字的按钮不重复添加 tooltip。
- 表格使用 `.table-responsive > .table.card-table` 结构；状态使用 Tabler 语义徽标，交互行可使用官方表格 hover 样式。
- 表单使用 Tabler 表单控件，保留标签、辅助说明、校验状态和原生提交语义。邮件编辑与预览并列时保持可读的响应式双栏。
- 确认信息、字段校验、空态和分页继续复用项目既有布局及 View Cells，不为品牌化另造交互组件。

## 当前落地示例：考试券模块

考试券模块的全部页面均遵循上述规则：批次、库存和邮件记录列表采用响应式表格与一致的操作呈现；创建、编辑、导入、备注、核验和邮件确认表单按任务分组并适配窄屏；批次与单券详情突出关键标识和信息层级；接收人分发及邮件模板使用并列卡片布局。其他模块同样遵循本项目级规范；未纳入具体任务的页面不应被顺带重设计。
